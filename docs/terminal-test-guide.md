# 터미널 기능 테스트 가이드

## 🎯 테스트 목적
웹 터미널이 백엔드와 정상적으로 연결되어 kubectl 명령어를 실행할 수 있는지 확인합니다.

---

## 📋 사전 준비

### 1. 백엔드 서버 실행 확인
```bash
# 백엔드가 실행 중인지 확인
curl http://localhost:8000/health
```

**예상 결과:**
```json
{"status":"ok"}
```

### 2. PostgreSQL 실행 확인
```bash
docker ps | grep postgres
```

**예상 결과:**
```
cloud-trouble-training-service-postgres-1   Up X minutes   0.0.0.0:5432->5432/tcp
```

### 3. 프론트엔드 실행 확인
브라우저에서 `http://localhost:3000` 접속 가능해야 함

---

## ✅ 테스트 시나리오

### 테스트 1: 로그인 기능
**목적:** 사용자 인증이 정상적으로 작동하는지 확인

**절차:**
1. 브라우저에서 `http://localhost:3000` 접속
2. 로그인 화면이 표시되는지 확인
3. 테스트 계정으로 로그인:
   - 사용자명: `test`
   - 비밀번호: `1234`

**예상 결과:**
- ✅ 로그인 성공 후 터미널 화면으로 이동
- ✅ 상단에 세션 ID 표시
- ✅ 로그아웃 버튼 표시

**실패 시:**
- 401 에러: 계정이 없음 → Swagger UI에서 회원가입 필요
- 500 에러: 백엔드 에러 → 백엔드 로그 확인

---

### 테스트 2: 터미널 렌더링
**목적:** xterm.js 터미널이 정상적으로 표시되는지 확인

**절차:**
1. 로그인 후 터미널 화면 확인
2. 터미널 영역이 검은색 배경으로 표시되는지 확인
3. 커서가 깜빡이는지 확인
4. `$ ` 프롬프트가 표시되는지 확인

**예상 결과:**
- ✅ 검은색 터미널 화면
- ✅ 깜빡이는 커서
- ✅ `$ ` 프롬프트

**실패 시:**
- 터미널이 안 보임: 브라우저 콘솔에서 에러 확인
- dimensions 에러: 페이지 새로고침

---

### 테스트 3: WebSocket 연결
**목적:** 프론트엔드와 백엔드가 WebSocket으로 연결되는지 확인

**절차:**
1. 터미널 상단의 연결 상태 확인
2. 브라우저 개발자 도구 → Network 탭 → WS 필터
3. WebSocket 연결 확인

**예상 결과:**
- ✅ 상단에 "🟢 연결됨" 표시
- ✅ Network 탭에 `ws://localhost:8000/ws/terminal/...` 연결 표시
- ✅ Status: 101 Switching Protocols

**실패 시:**
- 🔴 연결 안 됨: 백엔드 WebSocket 엔드포인트 확인
- 4001 에러: 토큰 문제 → 다시 로그인

---

### 테스트 4: 기본 명령어 실행
**목적:** kubectl 명령어가 정상적으로 실행되는지 확인

#### 4-1. kubectl get pods
```bash
kubectl get pods
```

**예상 결과:**
```
NAME                     READY   STATUS    RESTARTS   AGE
web-app-7d8f9c5b6-x4k2m  1/1     Running   0          5m
```

또는 빈 목록:
```
No resources found in user-xxx namespace.
```

**실패 시:**
- "Only kubectl commands are allowed": 정상 (다른 명령어 차단)
- 응답 없음: WebSocket 연결 확인

---

#### 4-2. kubectl get services
```bash
kubectl get services
```

**예상 결과:**
```
NAME          TYPE        CLUSTER-IP      EXTERNAL-IP   PORT(S)    AGE
web-service   ClusterIP   10.96.0.1       <none>        80/TCP     5m
```

또는 빈 목록

---

#### 4-3. kubectl get namespaces
```bash
kubectl get namespaces
```

**예상 결과:**
- 네임스페이스 목록 표시
- 또는 권한 에러 (정상 - 사용자는 자신의 네임스페이스만 접근 가능)

---

### 테스트 5: 입력 처리
**목적:** 사용자 입력이 정상적으로 처리되는지 확인

**절차:**
1. 터미널에 텍스트 입력
2. Backspace 키로 삭제 테스트
3. Enter 키로 명령어 실행

**예상 결과:**
- ✅ 입력한 문자가 화면에 표시됨
- ✅ Backspace로 문자 삭제 가능
- ✅ Enter로 명령어 전송

---

### 테스트 6: 에러 처리
**목적:** 잘못된 명령어에 대한 에러 처리 확인

#### 6-1. kubectl이 아닌 명령어
```bash
ls
```

**예상 결과:**
```
Error: Only kubectl commands are allowed
```

#### 6-2. 존재하지 않는 kubectl 명령어
```bash
kubectl invalid-command
```

**예상 결과:**
- 백엔드에서 에러 메시지 반환
- 빨간색으로 에러 표시

---

### 테스트 7: 삭제 명령어 확인
**목적:** 위험한 명령어에 대한 확인 다이얼로그 테스트

**절차:**
1. 삭제 명령어 입력:
```bash
kubectl delete pod test-pod
```

2. 확인 다이얼로그 표시 확인
3. "확인" 또는 "취소" 선택

**예상 결과:**
- ✅ 확인 다이얼로그 표시
- ✅ "확인" 선택 시 명령어 실행
- ✅ "취소" 선택 시 명령어 취소

---

### 테스트 8: 실시간 응답
**목적:** 명령어 실행 결과가 실시간으로 표시되는지 확인

**절차:**
1. 명령어 입력 후 Enter
2. 응답 시간 측정
3. 응답이 터미널에 표시되는지 확인

**예상 결과:**
- ✅ 1-2초 이내 응답
- ✅ 응답이 터미널에 즉시 표시
- ✅ 새로운 `$ ` 프롬프트 표시

---

### 테스트 9: 로그아웃
**목적:** 로그아웃 기능이 정상적으로 작동하는지 확인

**절차:**
1. 상단의 "로그아웃" 버튼 클릭
2. 로그인 화면으로 이동하는지 확인

**예상 결과:**
- ✅ 로그인 화면으로 이동
- ✅ WebSocket 연결 종료
- ✅ 세션 정보 초기화

---

### 테스트 10: 창 크기 조절
**목적:** 브라우저 창 크기 변경 시 터미널이 자동으로 조절되는지 확인

**절차:**
1. 브라우저 창 크기 조절
2. 터미널 크기가 자동으로 조절되는지 확인

**예상 결과:**
- ✅ 터미널이 창 크기에 맞춰 자동 조절
- ✅ 스크롤바 정상 작동

---

## 🐛 문제 해결

### 문제 1: 로그인 실패 (401)
**원인:** 계정이 없음

**해결:**
```bash
# Swagger UI에서 회원가입
# http://localhost:8000/docs
# POST /api/auth/register
{
  "username": "test",
  "password": "1234"
}
```

---

### 문제 2: 터미널이 안 보임
**원인:** xterm.js 렌더링 에러

**해결:**
1. 브라우저 콘솔 확인 (F12)
2. 페이지 새로고침 (F5)
3. 브라우저 캐시 삭제

---

### 문제 3: WebSocket 연결 실패
**원인:** 백엔드 WebSocket 엔드포인트 문제

**해결:**
1. 백엔드 로그 확인
2. 백엔드 재시작
3. 세션 ID 확인

---

### 문제 4: 명령어 응답 없음
**원인:** Kubernetes 클러스터 연결 문제

**해결:**
1. 백엔드 로그에서 kubectl 에러 확인
2. Kubernetes 클러스터 상태 확인
3. 네임스페이스 권한 확인
