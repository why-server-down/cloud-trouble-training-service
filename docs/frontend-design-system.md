# AfterFail 프론트 디자인 시스템

이 문서는 2026-10 프론트 디자인 개편(FE-24~FE-28)의 기준이다. 화면을 고치거나 새로 만들 때
여기 적힌 토큰·규칙을 먼저 따른다. 값이 필요한데 여기 없으면 가장 가까운 토큰을 쓰고, 새 값을
만들어야 하면 이 문서에 먼저 추가한다.

## 1. 제품과 사용자

| 항목 | 결정 |
|---|---|
| 주 사용자 | 학부생의 자율 학습과 수업 실습. 캡스톤 시연·심사는 2차 목적이다 |
| 사용 상황 | 노트북(1366×768 ~ 1440×900)에서 터미널을 치며 장애를 조사한다. 모바일(390×844)에서도 미션 하나를 끝까지 완주할 수 있어야 한다 |
| 접근성 목표 | WCAG 2.2 AA |
| 제품의 차별점 | 실제 장애가 주입된 환경을 터미널로 직접 다룬다. 화면의 주인공은 터미널이다 |

시연 전용 기능(AI 문제 잠금 해제)은 학생 화면에 보이지 않게 `?demo=1` 뒤로 둔다.
환경 로드맵(후속 연구 등)은 작업 화면이 아니라 환경이 닫혀 있을 때의 안내와 프로필에서만 보인다.

## 2. 방향: 터미널 워크벤치 + Apple 재질 규칙

- 다크 콘솔 정체성은 유지한다. 바탕은 어둡고, 강조색은 신호 주황 하나다.
- 장식을 걷어낸다. 모눈 배경, 영문 대문자 eyebrow(`RUNBOOK / INCIDENT QUEUE`, `OPS / 01`),
  3px 액센트 줄, 딱딱한 오프셋 그림자(`8px 8px 0`)를 쓰지 않는다.
- 비운 자리를 Apple의 재질·모션 규칙으로 채운다. 면의 위계는 밝기 단계와 둥근 모서리, 부드러운
  그림자로 만든다. 떠 있는 제어 계층만 반투명 재질을 쓴다.
- 문구는 한국어다. 고유명사(Kubernetes, Docker, Linux, Grafana)와 명령어만 영어로 둔다.

버린 대안: 라이트 프레임의 "장애 실험 노트", 전면 글래스, 라이트·다크 동시 지원.

## 3. 토큰

모든 값은 `frontend/src/index.css`의 `:root`에 있다. 컴포넌트 CSS에 색상 hex나 px 글자 크기를
직접 쓰지 않는다.

### 3.1 색

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | `#0b0d0c` | 앱 바탕 |
| `--surface-1` | `#121615` | 패널 |
| `--surface-2` | `#181d1b` | 카드, 입력창, 패널 안의 묶음 |
| `--surface-3` | `#202624` | hover·pressed, 선택된 세그먼트 |
| `--terminal-bg` | `#0a0c0b` | 터미널 본체 |
| `--fill-1` / `--fill-2` / `--fill-3` | 흰색 4% / 7% / 11% | 버튼·칩의 옅은 채움 |
| `--separator` | 흰색 8% | 1px 구분선 |

|---|---|
| 진행 중(LIVE) | `--accent` 점 + "진행 중" 글자 |
| 남은 시간 5분 미만 | `--warning` |
| 남은 시간 1분 미만 / 실패 | `--danger` |

색만으로 상태를 말하지 않는다. 항상 글자를 함께 쓴다.

### 3.2 글꼴과 크기

| 토큰 | 값 |
|---|---|
| `--font-sans` | `"IBM Plex Sans KR", -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Segoe UI", sans-serif` |
| `--font-mono` | `"IBM Plex Mono", "SF Mono", Menlo, Consolas, "IBM Plex Sans KR", monospace` |

모노 글꼴에는 한글 글리프가 없다. 스택 끝에 Plex Sans KR을 두어 한글이 굴림체로 떨어지지 않게
한다. **모노는 명령어, 리소스 이름, ID, 타이머, 점수, 터미널에만 쓴다.** 한국어 문장과 라벨은 항상
sans다.

| 토큰 | 크기 / 줄 높이 | 쓰는 곳 |
|---|---|---|
| `--text-xs` | 12px / 16px | 메타, 캡션, 칩. 화면의 최소 크기다 |
| `--text-sm` | 13px / 20px | 보조 UI, 라벨, 탭 |
| `--text-md` | 14px / 22px | UI 기본, 버튼 |
| `--text-lg` | 16px / 26px | 읽는 글: 브리핑의 미션 설명, 튜터 답변. 목록 카드의 요약은 `--text-md` |
| `--text-xl` | 20px / 28px | 섹션 제목 |
| `--text-2xl` | 28px / 34px | 화면 제목, 큰 숫자, 타이머 |

- 굵기는 400 / 500 / 600 세 가지만 쓴다. 제목 600, 라벨 500, 본문 400.
- 자간은 기본값이다. 한국어에 넓은 자간과 대문자 변환을 쓰지 않는다.
- 숫자가 바뀌는 곳(타이머, 점수)은 `font-variant-numeric: tabular-nums`.

### 3.3 간격, 모서리, 그림자

| 토큰 | 값 |
|---|---|
| `--space-1`~`--space-10` | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40px (`--space-1`=4, `--space-2`=8, `--space-3`=12, `--space-4`=16, `--space-5`=20, `--space-6`=24, `--space-8`=32, `--space-10`=40) |
| `--radius-sm` | 6px — 칩, 작은 버튼, 코드 |
| `--radius-md` | 10px — 버튼, 입력창, 카드 |
| `--radius-lg` | 14px — 패널 |
| `--radius-xl` | 20px — 시트 |
| `--shadow-1` | 떠 있는 작은 요소(호버된 카드, 칩 메뉴) |
| `--shadow-2` | 팝오버, 토스트, 플로팅 튜터 |
| `--shadow-3` | 시트 |

**고정된 작업 패널은 평평하다.** 둥근 모서리와 `--separator` 테두리만 쓰고 그림자를 주지 않는다.
그림자와 재질은 실제로 떠 있는 것(시트, 팝오버, 토스트)에만 쓴다. 모든 면에 하이라이트·그림자·
스프링을 일괄로 주면 흔한 생성형 대시보드처럼 보인다.

선택 상태는 배경 밝기만으로 구분하지 않는다(`--surface-3`과 주변의 대비는 1.2:1이다). 강조색
글자·표시선·체크 중 하나를 함께 쓴다.

### 3.4 모션

| 토큰 | 값 |
|---|---|
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` |
| `--ease-spring` | `cubic-bezier(0.34, 1.3, 0.64, 1)` — 시트 등장처럼 살짝 넘치는 움직임 |
| `--dur-fast` / `--dur-base` / `--dur-slow` | 120ms / 200ms / 320ms |

`prefers-reduced-motion: reduce`에서는 이동·확대 없이 120ms 크로스페이드만 쓴다.

## 4. 재질(글래스) 규칙

글래스는 **콘텐츠 위에 떠 있는 제어 계층**에만 쓴다. 터미널, 미션 설명, 튜터 답변 본문, 카드,
대시보드 지표는 불투명하다. macOS 앱의 사이드바·툴바는 반투명하고 편집기 본문은 불투명한 것과
같은 원칙이다.

| 재질 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--material-bar` | 바탕 72% + `blur(20px) saturate(160%)` | 모바일 하단 탭 바, 스크롤되는 헤더 |
| `--material-sheet` | 바탕 80% + `blur(28px) saturate(170%)` | 시작 시트, 디브리프 시트, 프로필 시트 |
| `--material-popover` | 바탕 84% + `blur(24px)` | 투어 카드, 토스트 |

- 시트는 scrim(`rgba(0,0,0,0.5)`)으로 뒤를 누른다. 등장할 때 투명도·scale(0.96→1)을 함께 움직인다.
- 보조 패널(브리핑/튜터/관측)은 뒤에 흐르는 콘텐츠가 없으므로 글래스가 아니라 **불투명한 평평한
  패널**(`--surface-1` + `--radius-lg` + `--separator`)이다. 단색 위 글래스는 회색 상자로 보인다.
- 인시던트 바는 터미널 출력 위에 겹치지 않는다. 터미널 위에 전용 높이를 가진 **불투명 툴바**로 둔다
  (작은 블러라도 계속 다시 그려지는 캔버스 위에서는 비용이 든다).
- xterm 캔버스 위에 **계속 떠 있는 면**은 `backdrop-filter`를 쓰지 않는다. 계속 다시 그려지는 캔버스
  위에서는 출력마다 블러를 다시 계산한다. 잠깐 뜨는 시트는 예외다 — 시트가 열리면 포커스가 시트로
  옮겨가 터미널 커서가 깜박이지 않으므로 뒤 캔버스가 거의 다시 그려지지 않는다.
- 시트는 한 번에 하나만 키보드를 받는다. 겹치면(프로필 위 확인 시트) 위에 뜬 시트만 Esc·Tab을
  처리하고, 시트가 열려 있는 동안 앱 본문은 `inert`다.
- 반투명 면 위에 반투명 면을 쌓지 않는다.
- 반투명 면 위의 글자는 `--text`(회색 금지)를 쓰고 한 단계 굵게 한다.
- 1px 구분선 대신, 떠 있는 바와 콘텐츠가 겹치는 경계에만 얕은 그라디언트 마스크를 둔다.
- 대체 경로는 반드시 둔다.
  - `@supports not (backdrop-filter: blur(1px))` → 불투명 `--surface-1`
  - `prefers-reduced-transparency: reduce` → 불투명
  - `prefers-contrast: more` → 거의 불투명 + `--separator-strong` 테두리

## 5. 컴포넌트 규칙

### 5.1 버튼

`frontend/src/index.css`의 공용 클래스를 쓴다.

| 클래스 | 모양 | 한 화면에 |
|---|---|---|
| `.ui-button.primary` | `--accent` 채움, `--text-on-accent` 글자 | 하나 |
| `.ui-button` (기본) | `--fill-2` 채움, `--separator` 테두리 | 여러 개 |
| `.ui-button.plain` | 배경 없음, `--text-secondary` | 취소·닫기 |
| `.ui-button.danger` | 배경 없음, `--danger` 글자. 확정 버튼일 때만 `--danger` 채움 | 다른 버튼과 떨어뜨려 둔다 |

- 높이 36px(기본), 32px(`.small`). `pointer: coarse`에서 최소 44px.
- 비용이 있는 동작은 비용을 버튼에 적는다: `힌트 사용 −10점`.
- 진행 중에는 라벨을 진행형으로 바꾼다(`확인 중...`)

### 5.2 포커스

모든 상호작용 요소에 `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }`.
마우스 클릭에는 링을 그리지 않는다.

### 5.3 칩과 배지

`--text-xs`, `--radius-sm`, 높이 22px, `--fill-1` 배경. 환경 배지는 글자로 환경을 밝힌다.

### 5.4 섹션 머리

eyebrow 대신 `--text-sm` 500 `--text-secondary` 섹션 라벨 + 필요하면 오른쪽에 상태 칩. eyebrow는
상태를 담을 때만 쓴다(`진행 중 · 19:41`).

### 5.5 빈 상태와 오류

- "데이터 없음"과 0을 구분한다. 없으면 `—`와 이유 문장.
- 오류는 무엇이 실패했는지 + 사용자가 할 수 있는 일(다시 시도 버튼)을 함께 쓴다.
- 오류 토스트는 자동으로 사라지지 않는다. 성공·안내 토스트만 4초 뒤 사라진다.

## 6. 화면 구조

### 6.1 작업 화면 — 영역 네 개

| 영역 | 미션 전 | 미션 중 |
|---|---|---|
| 미션 | 미션 목록 + AI 문제 | 브리핑: 미션 설명, 조사 순서, 조사 명령(눌러서 터미널에 입력) |
| 터미널 | 시작 가이드 | 인시던트 바 + 터미널 |
| 튜터 | (없음) | AI 튜터 대화 |
| 현황 | 학습 현황 대시보드 | 관측(Grafana) |

- **데스크톱 미션 전**: `미션(380px) | 시작 가이드 | 학습 현황`.
- **데스크톱 미션 중**: `터미널(남는 폭 전부, 55% 이상) | 보조 패널(400px)`. 보조 패널은
  `브리핑 / 튜터 / 관측` 세그먼트로 전환한다.
- **모바일(≤768px)**: 한 번에 한 영역. 하단 탭 바(`미션 / 터미널 / 튜터 / 현황`)로 전환한다.
  헤더는 한 줄이다.
- 영역은 화면에서 감춰도 **언마운트하지 않는다.** 터미널 WebSocket, 스크롤백, 튜터 대화가
  탭 전환으로 사라지면 안 된다.

### 6.2 인시던트 바

터미널 위에 전용 높이를 가진 불투명 툴바(`--surface-1`). 터미널 출력 위에 겹치지 않는다. 왼쪽에
진행 중 표시와 미션명, 가운데에 타이머(`--text-xl` 모노, tabular-nums — 미션 목표보다 커 보이지
않게)와 점수·힌트, 오른쪽에 동작.

- `완료 확인` = 1차 버튼
- `힌트 사용 −N점` = 기본 버튼
- `포기` = 위험 버튼, 구분선으로 떨어뜨린다

### 6.3 미션 생명주기

1. **시작 시트**: 미션명, 환경, 제한 시간, 점수 규칙(기본 점수, 시간 감점, 힌트 감점), "시작하면
   내 네임스페이스에 장애가 주입됩니다" 안내. 첫 미션이면 투어를 시작 **전에** 제안한다.
2. **진행**: 인시던트 바. 남은 시간이 5분·1분 아래로 내려가면 색과 글자로 알린다.
3. **디브리프 시트**: 완료·시간 초과·포기 모두 같은 시트. 결과, 서버가 준 최종 점수, 걸린 시간,
   사용한 힌트, 무엇이 문제였는지(완료 후에만). 점수는 프론트에서 계산하지 않는다.

### 6.3.1 힌트

`힌트 사용 −N점`을 누르면 확인 시트가 깎이는 점수와 받는 것을 말하고, 확정하면 튜터 탭이 열리며
올라간 단계의 힌트를 튜터가 바로 보여 준다. 점수만 깎이고 화면에 아무것도 나오지 않으면 안 된다.
튜터 질문 자체는 감점이 없다(시간·힌트로만 깎인다).

### 6.4 프로필

작업 화면을 대체하지 않는 시트(데스크톱 오른쪽 드로어, 모바일 전체 시트)다. 열려 있어도 터미널과
튜터 대화가 유지된다.

### 6.5 터미널 입력

- 입력줄은 셸처럼 편집된다: ←/→, Home/End(Ctrl+A/E), Delete, Ctrl+U/W, ↑/↓ 이력.
  한글은 두 칸으로 계산한다. 줄 편집 로직은 `utils/lineEditor.ts`(순수 함수, 단위 테스트)에 있다.
- **Esc는 터미널에서 빠져나간다.** Tab은 자동완성에 쓰이므로 키보드 트랩을 만들지 않으려면
  나가는 키가 따로 있어야 한다. 헤더에 `Esc: 터미널에서 나가기`를 늘 보여 준다(터치 기기 제외).
- 여러 줄 붙여넣기는 바로 실행하지 않고 확인 시트로 무엇이 실행될지 보여 준다.
- 브리핑의 조사 명령은 실행하지 않고 입력줄에만 넣고, 명령마다 출력에서 볼 곳을 함께 적는다.
- 마우스·키보드 환경에서는 터미널이 열리면 바로 focus 를 준다. 터치 기기는 가상 키보드가
  화면을 가려 사용자가 누를 때만 연다.

## 7. 문구

| 이전 | 이후 |
|---|---|
| `GUIDE` | `둘러보기` |
| `SKIP` / `NEXT` / `DONE` | `건너뛰기` / `다음` / `완료` |
| `LOCKED / ` | `잠김` 칩 + 열리는 조건 |
| `Level 1` | `레벨 1` |
| `Beginner` 등 | `입문` / `중급` / `고급` / `전문가` |
| `LIVE INCIDENT` | `진행 중` |
| `RUNBOOK / INCIDENT QUEUE` 등 eyebrow | 삭제 또는 한국어 섹션 라벨 |
| `힌트 단계 0` | `힌트 0단계 · 쓸수록 구체적으로 안내합니다` |
| `MTTR` | `평균 복구 시간(MTTR)` 처음 한 번 풀어 쓴다 |

환경·상태를 정직하게 말하는 문구(잠긴 탭의 이유, 데이터 없음과 0의 구분, 튜터 환경 불일치 경고)는
개편 후에도 그대로 지킨다.

## 8. 접근성 체크리스트

- 본문 대비 4.5:1 이상, 큰 글자·아이콘 3:1 이상. 플레이스홀더 색도 지정한다.
- 잠긴 카드는 `disabled` 대신 `aria-disabled`로 Tab 순서에 남겨 이유를 읽을 수 있게 한다.
- 모달·시트: 포커스 트랩, Esc 닫기, 닫힌 뒤 포커스 복귀. 위험한 확정 동작에는 기본 포커스를
  두지 않는다(포기 확인은 `취소`에 포커스).
- 투어는 열릴 때 카드로 포커스를 옮긴다.
- 로그인 오류는 `role="alert"`.
- 터치 영역 44px 이상(`pointer: coarse`).
- 화면 크기: 1366×768, 768×1024, 390×844에서 핵심 흐름을 끝까지 완료할 수 있어야 한다.

## 9. 하지 않는 것

- 새 runtime 의존성 추가(상태 관리, 라우터, 차트, UI 키트, 폰트 패키지). IBM Plex Mono는
  `frontend/src/assets/fonts/`에 woff2로 직접 둔다(OFL).
- 배경 그라디언트 블롭, 콘텐츠 위 글래스, 글래스 위 글래스.
- 환경별 CSS 통째 복제. 환경별로는 배지 색과 소수 토큰만 바꾼다.
- 프론트에서 점수 계산·확정.
